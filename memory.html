한 장면에서 공간을,
한 이미지에서 물건을.

여러 참조를 대조했지만, 여러 시점의 사진을 묶어
정확한 공간을 삼각측량한 작업은 아닙니다.

장면의 입력 — 생성하지 않은 실제 프레임

명조 3장 5막의 공개 플레이 영상 01:43:43 프레임과 사용자 참조 다섯 장을 대조했습니다. 원본은 1920×1080. 검은 띠만 (0,135)–(1920,945)로 잘라 1920×810을 만들고, 이 단일 이미지를 장면 추론에 넣었습니다. 이 입력에는 이미지 생성·인페인팅·샤프닝을 적용하지 않았습니다.

Apple SHARP는 한 이미지에서 3D Gaussian의 파라미터를 추론합니다. 이 제작에서는 공식 고정 커밋과 sharp_2572gikvuh.pt를 사용했습니다. 원래 장면의 가려진 뒷공간이 관측된 것처럼 복원된다는 뜻은 아닙니다.

출력 — 단순한 색 점 이상의 Gaussian

출력 PLY에는 점의 위치·SH0 색·opacity뿐 아니라 축별 scale과 회전 quaternion이 있습니다. 넓이와 방향을 가진 Gaussian을 화면에 투영·정렬·합성해 공간으로 보이게 합니다. 점의 수만으로 정확도나 보이지 않던 구조의 진실성을 판단하지 않습니다.

초기 실행 기록은 RTX 4060 8GB / CUDA float32, 모델 내부 1536×1536 입력입니다. EXIF 초점 정보가 없어 공식 기본 30mm를 사용했습니다. 장면의 렌즈·좌표는 추론과 등록의 조건이며 실제 게임 카메라의 실측값이 아닙니다.

초기 raw-sharp.ply는 66,061,086바이트입니다. 공식 저장 과정의 inverse-sigmoid에서 alpha=1인 여섯 opacity만 +Inf가 되어, 호환 파생 PLY에서 logit 16.11809555로 바꿨습니다. 위치·색·scale·회전·개수는 이 단계에서 바꾸지 않았습니다.

Spark 2.4.0의 transcodeSpz로 SPZ3 / fractionalBits16 압축을 수행한 초기 파일은 16,548,216바이트였습니다. 양자화를 포함하는 압축이며, clipping·filtering 없이 같은 점 수를 유지한 결과입니다. 이후 카세트 점을 선택 제거한 현재 SPZ는 16,263,649바이트이며, 두 파일을 구분합니다.

초기 물건 복원 — 별도의 생성 입력과 TripoSR

넓게 돌릴 물건은 원본의 가린 부분을 그대로 관측할 수 없었습니다. 사용자가 허용한 생성형 보완으로 참조에서 손·배경을 분리하고 작은 가림을 완성한 저장 이미지를 만들었습니다. 그 이미지를 TripoSR에 넣어 22,833정점·45,650삼각형의 초기 메시를 만들고, 앞면에 입력 이미지를 투영했습니다.

초기 생성 이미지1880×837은 foreground ratio .85로 정렬·패딩한1994×1994 입력으로 준비했습니다. 초기 실행은 float32·chunk4096·marching cubes192였습니다. Windows/Python3.12의 torchmcubes 문제로 표면 추출만 scikit-image CPU 어댑터로 대체하고 신경망 가중치는 유지했습니다. 초기 GLB는 1,866,352바이트이며 후면과 두께는 생성 추정입니다.

서로 다른 모델 계보

현재 카세트를 초기 TripoSR 출력의 단순 경량화라고 설명하지 않습니다. 최신 Act5는 이후 별도로 제공된 aemeath_cassette.glb를 출발점으로 앞면 UV를 보존하고 뒤·옆면과 뒷판을 보완했습니다. 초기 SHARP·TripoSR 제작, 후속 제공 모델의 정리, 이번 CVA 채택은 각각 다른 단계입니다.

고정 버전·당시 실행 기록·다시 만들 수 있는 범위

저장된 입력·스크립트·로그가 이후 단계의 재실행 기준입니다. 생성형 이미지의 동일 프롬프트가 같은 픽셀을 보장하지 않으며, 새 환경 설치나 GPU 차이까지 재검증한 것은 아닙니다. 모델 가중치·가상환경은 웹 키트에 포함하지 않습니다. SHARP 코드와 모델의 라이선스는 별도이며 모델의 연구용 조건을 확인해야 합니다. TripoSR의 MIT와 게임 시각 자료의 권리도 구분합니다.

01 / OBJECT IDENTITY

더 닮게 만드는 것보다,
같은 물건을 남기는 일.

사진 속 테이프와 별도 모델이 겹치는 문제는
테이프를 더 휘게 만들어 해결할 수 없었습니다.

문제 — 회전하면 두 개의 테이프

Gaussian 장면 안에도 테이프가 있고, 그 위에 올린 GLB에도 테이프가 있었습니다. 서로 다른 깊이와 형상이 회전 중 벌어지면서 이중 윤곽이 생겼습니다. 반투명 교대를 길게 하면 이 어긋남도 오래 보였습니다.

중간 개선에서는 완성된 두 화면을 old × g + new × (1 − g)로 합성했습니다. 개별 splat의 alpha를 낮추는 방식보다 교대가 안정적이었지만, 중복된 표현은 여전히 존재했습니다.

선택 — 처음부터 끝까지 rigid 모델 하나

최신 방식은 장면에서 카세트에 해당하는 점만 제외하고, 같은 rigid GLB를 처음부터 유지합니다. 카메라가 가까워져도 물건이 교체되지 않고 주변만 물러납니다. 사진 속 모양에 맞추려 모델을 비선형으로 구부린 초안은 폐기했습니다.

점 중심을 원본 시점으로 투영해 깊이·제거 polygon·보존 polygon으로 선택합니다. SPZ3/SH0의 남은 속성 row는 그대로 복사하고 count를 갱신합니다. 원본은 별도 보존하며, 새 Gaussian 학습을 한 것으로 설명하지 않습니다.

앞면은 보존하고, 보이지 않던 면은 구분해서 보완했습니다.

후속 제공 모델의 82개 primitive를 정리해 뒷판을 포함한 약 4,500개 삼각형으로 만들었습니다. 제공된 카세트 모델에서 관측된 앞면 그림과 UV를 유지했습니다. 서로 다른 깊이의 뒤쪽 부품에는 얇은 둥근 뒷판을 더해 회전 시 틈이 갈라져 보이지 않게 했습니다. 후면은 world-plane, 옆면은 방향에 따른 box projection으로 텍스처를 연결하고 재질별 다섯 mesh로 정리했습니다.

보완한 후면이 bounds를 키워도 앞면이 움직이지 않도록, 매번 bounds에 끼워 맞추는 대신 고정 XYZ basis와 offset으로 등록했습니다. 릴은 ELIO_Reel_Anchor에서 같은 월드 변환을 따릅니다. 후면·두께·재질은 팬 시각 근사이며 공식 게임 모델이나 실측 복원이 아닙니다.

기존 제작 기록: GLB 2,343,280 → 863,360바이트. 형상·UV buffer와 texture 재인코딩을 구분했습니다. 앞면 JPEG92·후면 JPEG85·작은 옆면 JPEG82는 손실 압축이며, 이전 원본과 고품질 출력은 복구 근거입니다. 기존 glTF Validator 오류·경고 0 기록을 이번 재생 검수에서 새로 측정한 결과로 소개하지 않습니다.

CVA에 남길 판단

표현을 바꿀 때는 무엇을 같은 대상으로 인식해야 하는지부터 정합니다. 유물 복원에는 관측면과 추정면, 지도에는 장소 ID, 차트에는 항목·단위·필터가 그 기준이 됩니다. 이 카세트의 등록 행렬과 제거 polygon은 다른 자료에 복사할 규칙이 아닙니다.

현재 자세와 속도의 책임

일반 휠 목표 변경은 critically damped update로 진행 속도를 이어 갑니다. 사용자가 직접 잡는 순간은 손에 맞춰 멈추는 경계입니다. 자동 관람과 수동 회전 offset은 분리했습니다. idle의 hard clamp가 만들던 멈칫거림은 제한 진폭의 연속 회전으로 정리했습니다.

초기에는 진입 tangent와 회전 예산을 실험했습니다. 최신 Read는 실제 현재 자세에서 시작해 원래 film 방향을 따르며, 명시한 endProgress에서는 초기 진행 속도 0과 정해진 duration을 씁니다. pitch·focus·reel·roll은 시작값으로 고정합니다. 모든 축이 C1 연속이라는 주장은 하지 않습니다.

03 / MASK & LIGHT

물건을 지우는 빛에서,
다음 화면을 여는 빛으로.

마스크와 글로우는 미리 저장한 예쁜 모양이 아니라,
지금 카메라에 보이는 테이프의 윤곽을 따릅니다.

고정 원형과 작은 래스터 마스크의 한계

작은 마스크를 확대하면 계단이 보이고, 저장 시점과 현재 회전이 다르면 입구가 대상에서 벗어납니다. 최신 viewer는 모델의 outer hull을 현재 카메라에서 투영하고 host에 전달합니다. 화면의 letterbox·여백 변환은 한 번만 적용합니다.

host는 convex outline을 둥근 SVG path로 만들어 대상 core와 주변 파동에 사용합니다. 오목한 구멍이 중요한 부품이나 여러 물체에는 이 convex 윤곽이 의미를 잃을 수 있으므로 그대로 일반화하지 않습니다.

각 레이어에 서로 다른 일을 맡기기

core는 테이프 자리부터 열고, 넓은 feather는 주변을 걷고, 장면 opacity는 따로 줄입니다. 바깥 halo는 흐리되 내부는 선명한 cutout으로 잘라 표면을 보호합니다. 전체를 큰 blur 하나로 희게 덮는 방식에서 벗어났습니다.

먼 구도부터 윤곽을 준비해 빛이 늦게 갑자기 켜지지 않게 합니다. 이것은 다음 화면으로 시선을 인계하는 합성 표현이며, 테이프가 실제로 발광하거나 재질의 물리 특성이 바뀐다는 뜻은 아닙니다.

실제 GPU의 승인된 장면에서 Gaussian LoD를 끄고 source target과 canvas를 모두 3414×1440으로 맞췄습니다. Spark의 sort/update 뒤 실제 draw와 outline을 캡처합니다. 저해상도 사진 한 장과 mesh의 조합, 소프트웨어 GPU로 흐리게 캡처한 결과는 깊이·선명도를 유지하지 못해 채택하지 않았습니다.

기존 제작 기록은 Whale 5.39 / RTX 5070 Ti, 전체 잔존 점 1,163,563개에서의 캡처입니다. 이번 CVA 채택에서 그 GPU 캡처를 다시 수행했다는 뜻은 아닙니다.

가속 유무에 맞춰 표현을 선택

실제 renderer가 GPU면 live Gaussian·GLB, software이거나 WebGL을 만들 수 없으면 AVIF 이미지 플레이어를 사용합니다. 정보가 가려진 unknown은 별도 예산의 live 경로입니다. 브라우저 이름이나 WebGPU 존재만으로 가속 여부를 단정하지 않습니다.

이미지는 정·역방향 접근과 작성된 궤도를 제공하지만 자유 시점 3D 회전은 제공하지 않습니다. 과거 native video seek·dissolve는 비교 실험의 역사이고, 현재 자동 software 기본 경로는 이미지 재생입니다.

1080 세트는 14,881,465바이트

압축 파일을 받는 일과 픽셀을 메모리에 여는 일은 다릅니다.

압축 바이트 캐시는 64MiB, fetch는 2개로 제한합니다. decoded bitmap은 4장, decoder는 1개, lookahead는 1장입니다. 고해상도 수백 장을 모두 decoded 상태로 쌓지 않습니다. 현재 목표를 우선하고 더는 필요 없는 bitmap을 닫습니다.

빠르게 역방향으로 돌리거나 크기를 바꾼 뒤 늦게 끝난 decode는 epoch·현재 요청을 대조해 버립니다. metadata는 target을 요청했을 때가 아니라 실제 paint가 끝난 프레임에서 보냅니다. 따라서 이미지·마스크·카메라 정보가 같은 프레임을 가리킵니다.

AVIF는 이미 손실 압축된 WebP에서 변환한 파생물입니다. 서로 다른 코덱의 Q50과 Q90은 같은 품질 척도가 아닙니다. RAF 60회와 서로 다른 이미지가 초당 60장 표시되는 것도 다릅니다. 캐시·동시성 수치는 이 사례의 예산이며 CVA 전체의 고정 기본값으로 강제하지 않습니다.

해상도·압축·재사용을 결정한 과정

최초 표시 영역의 letterbox 높이와 DPR에서 1440·1080 세트 중 하나를 고르고 페이지 동안 유지합니다. resize마다 세트를 바꾸며 다시 내려받기보다 기존 바이트를 재사용하는 선택입니다. 과거 직접 WebP Q80 세트는 37,673,116바이트였고, 보존한 Q90 WebP에서 AVIF50으로 파생한 1440 세트는 21,251,044바이트입니다.

기존 제작 기록의 대표 12장 비교와 842장 decode·hash 확인은 그때의 품질·무결성 근거입니다. 한 페이지 안의 421 fetch 재사용도 영구 offline 보장을 뜻하지 않습니다. 작은 decode 표본의 결과를 모든 장치의 전체 재생 FPS로 확대하지 않습니다.

05 / READING, INPUT & RECOVERY

카메라가 멈춘 뒤에도,
경험은 계속됩니다.

장면의 끝, 문장을 읽는 시간, 사용자가 다시 움직일 수 있는 시간.
서로 다른 세 사건을 하나로 묶지 않았습니다.

글자도 카메라와 함께 배치합니다.

넓은 구도에서는 큰 제목이 장면의 맥락을 잡고, 근접할수록 물건의 윤곽과 표면을 주역으로 남깁니다. 제목·질문·상태·주 행동의 크기와 명암을 다르게 두고, 필수 문장은 canvas나 잘리는 mask 안에만 넣지 않습니다. 질문이 테이프 위를 가리던 구간은 안정된 위쪽 여백으로 옮겼습니다. 본문은 읽는 폭을 제한하고 모바일에서는 한 열로 다시 배치합니다. 빛과 글자의 등장 순서가 경쟁하면 장식을 더하기 전에 움직임과 문장을 순서대로 놓습니다.

보이기 시작한 본문을 실제로 쓸 수 있게

opacity를 0으로 만드는 것만으로는 dialog의 모달·inert·키보드 잠금이 풀리지 않습니다. 본문이 충분히 열린 시점에 실제 조작권을 반환하고, 남은 veil은 비모달·입력 불가 상태로 정리합니다. 마지막 cleanup이 사용자가 이미 옮긴 scroll과 focus를 다시 덮지 않게 했습니다.

Watch는 장면 iframe만 걷고 필수 문장은 그 밖에 남깁니다. 팝업이 막히면 실제 링크와 계속 읽기를 유지하며, 새 탭이 생겼다는 사실을 영상이 재생됐다는 검증으로 확대하지 않습니다.

첫 프레임과 도움말도 같은 상태를 따라

처음에는 작은 CSS로 제목과 cover를 보여 줍니다. poster decode와 같은 p0의 실제 paint가 준비된 뒤 450ms 인계와 idle을 시작합니다. 로딩 중 이미 돌아간 장면이 갑자기 나타나는 현상을 막기 위한 순서입니다.

도움말은 실제 지원 입력을 따릅니다. live는 드래그 회전·접근, 이미지는 스크롤·세로 쓸기입니다. Esc로 본문 복귀, 장면 다시 보기, 로딩 실패 시 직접 읽기 경로를 둡니다. 감소 모션 설정에서는 본문부터 열고 사용자가 장면을 선택할 수 있게 했습니다.

툴팁·온보딩에 적용할 기준

핵심 행동을 투어 뒤에 숨기지 않습니다. 설명 없이 발견하기 어려운 조작만 짧게 안내하고, 닫기·건너뛰기·다시 보기를 제공합니다. tooltip은 hover뿐 아니라 focus에서도 열고 Esc로 닫으며, 반드시 읽어야 할 조건·결과는 본문에 남깁니다. 안내가 현재 선택과 입력을 가로채면 설명문을 더하기 전에 상태 책임을 고칩니다.

06 / WHAT CVA CAN TRANSFER

복사할 것은 화면이 아니라,
그 화면이 성립하는 관계.

다른 콘텐츠에서는 구도·재질·문장·시간을 다시 고릅니다.
대상·원인·표시·입력·회복의 계약을 공통 원리로 남깁니다.

01

대상의 정체성을 이어 준다

사진→모델은 관측면과 anchor, 지도→기록은 장소 ID, 차트→근거는 항목·단위·필터를 보존합니다. 전후가 실제로 달라야 하는 비교를 억지로 같은 물체처럼 연결하면 변화를 숨기므로 적용하지 않습니다.

02

원인 상태와 보는 방향을 분리한다

달의 공전 위치와 카메라 회전, 제품의 값과 조명은 다른 상태입니다. 하나의 의미 상태를 시각화와 설명이 함께 읽게 합니다. 단순 목록·관리 화면에는 불필요한 3D driver와 긴 서사를 추가하지 않습니다.

03

읽기·시각적 마무리·조작권에 각자의 시간을 준다

제품 분해는 카메라 도착 후 부품을 읽을 시간을, 문서 탐색은 즉시 비교·복귀할 권한을 우선합니다. Memory의 4.5초·6.35초·7.8초는 이 장면의 선택이지 모든 페이지의 모션 token이 아닙니다.

04

실제로 표시한 결과를 설명한다

프레임 decode, 지도 tile, 비동기 차트가 늦으면 라벨·tooltip도 현재 표시 상태를 따릅니다. 요청 중인 값과 확정된 결과를 구분하고, 늦게 도착한 이전 결과가 새 선택을 덮지 않게 합니다.

05

형식이 달라도 핵심 과업과 회복을 유지한다

실시간 3D와 사전 렌더, 데스크톱과 모바일은 지원 입력이 달라도 대상·진행·목적지·본문 복귀를 유지합니다. 지원하지 않는 자유 회전을 가능하다고 안내하거나 실제로 하지 않은 터치 검수를 했다고 말하지 않습니다.

06

품질과 근거의 경계를 함께 전달한다

유물의 추정 복원, 환경 흐름의 설명 입자, 게임 모델의 후면 보완은 관측 사실과 구분합니다. 해시 검사는 전송 무결성을, 실제 렌더는 보이는 결과를, 사용자 시험은 이해를 각각 확인합니다. 하나가 다른 증거를 대신하지 않습니다.

07 / EVIDENCE & LIMITS

작동한 것과,
아직 말할 수 없는 것.

이번 CVA 채택에서 직접 확인

  • 실제 live GS·GLB와 강제 이미지 경로의 로딩·표시.
  • 스크롤 접근·역방향 이동, live 드래그 회전, 현재 자세에서 Read, Esc, 본문 스크롤, 장면 재열기.
  • 390px 모바일 viewport의 실제 렌더와 가로 넘침 여부. 실제 모바일 하드웨어 입력 시험과 구분.
  • 고정 공개 자산의 GET·SHA256·CORS, 작은 코드·metadata와 원격 대용량 자산의 분리.

성공을 확대해서 말하지 않기

  • GPU 캡처 장치·glTF 검증은 소스 제작 기록입니다. 이번 CVA 채택에서 신경망 추론이나 모델 생성을 다시 실행하지 않았습니다.
  • 이미지 궤도 원본은 15개의 고유 프레임/초입니다. 60fps 성능을 입증한 결과가 아닙니다.
  • 실제 기기의 터치·모든 브라우저·네트워크 성능, 사용자의 이해 향상은 미검증입니다.
  • 원격 자산과 공식 라이브러리 CDN에 인터넷 연결이 필요합니다. 공개 발행은 포괄 상업 라이선스를 뜻하지 않습니다.

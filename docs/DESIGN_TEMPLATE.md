먼저 템플릿 선택기를 잊고 이 내용을 위한 완성 페이지를 그린다. **이 페이지를 직접 만든다고 생각해도 같은 구도·형태·조작을 고를 것인가?** 그렇지 않다면 모듈의 편의 때문에 생긴 구성을 고친다. 재사용할 것은 내용·상태·관계·접근성 책임이며, 카드 모양·패널 위치·3D 외형까지 같게 만들 필요는 없다.

상호작용이 있으면 무엇을 누르는지보다 **그 행동으로 무엇을 이해하게 되는지**를 적는다.

| 행동 | 바뀌는 상태 | 시각·텍스트·근거에 함께 나타날 변화 | 돌아오기·실패 처리 |
|---|---|---|---|
| <선택·시점·단계·입력 등 실제 행동> | <선택 ID·단계·선언 모델 입력 등> | <같은 대상을 가리키는 표현과 확인 가능한 의미> | <초기화·이전 단계·입력 복구·대체 읽기> |

정적인 문장으로 충분한 과업에 동작을 더하지 않는다. 3D·스크롤·계산은 공간 관계·이야기의 변화·입력의 결과를 이해하는 데 필요할 때 고른다. 템플릿의 항목 수·카드 수·색·배치에 맞추기 위해 내용을 바꾸거나, 정본 API가 지원하지 않는 속성·동작을 있다고 설명하지 않는다.

새로 작성하는 스크롤·프레임 서사는 같은 진행·직접 입력·모션 모드에서 정·역방향과 임의 seek의 결과가 같아야 한다. 문서 scroll은 native 조작과 반올림하지 않은 진행을 유지한다. 장 제목은 정보 구분이며 매번 멈추는 애니메이션 keyframe이 아니다. 움직임이 이어질 구간은 위치·변화율을 함께 연결하고, 읽기 hold는 필요한 곳에 직접 정한다. frame은 현재 프레임에서 평가하며 실시간 누적이나 시간에 따라 따라잡는 smoothing에 기대지 않는다. 기존 자유 관람 viewer를 보강하는 일에는 새 driver를 강제하지 않고 원본 입력·감쇠·재생 인계를 보존한다.

감소 모션에서는 무엇을 생략하고 어떤 의미 변화를 남길지 고른다. 예를 들어 장마다 카메라를 순간 이동시키는 대신 고정 구도에서 원인 변수·결과·문장을 연결한다. 모션 선택은 숨겨지는 직접 조절 패널 밖에서도 찾을 수 있어야 하며, 수동 입력·history·초기화를 건드리지 않는다. canvas·sticky의 크기는 문장 교체로 바뀌지 않게 한다. 실제 지원 API·구간·자막 안전 영역은 해당 구현이 있을 때 기록한다.

### 스크롤 장면의 편집이 필요한 경우

먼저 이 내용의 핵심 자세를 그린다. 제품의 윤곽·부품 사이의 연결·물이 갈라지는 지점·용량이 초과되는 순간처럼 **이해해야 할 관계가 실제로 보이는 구도**를 고른다. 장 수나 스크롤 길이를 채우는 표가 아니다. 대표 전환 하나부터 다음 항목으로 편집한 뒤 앞뒤로 실제 스크롤해 수정한다.

| 진행 범위·이 순간의 메시지 | 주역의 시작·도착 자세 | 준비 → 이동·변화 → 도착·읽기 | 설명·이름표·직접 입력 |
|---|---|---|---|
| <원시 진행 범위, 이해할 내용 하나> | <모델 상태, 카메라 주시점·방향·거리, 유지할 대상> | <어떤 track이 먼저 시작·완료되는가, 읽는 동안 무엇을 멈추는가> | <주역 곁에 남을 문장, 실제 투영 anchor, 현재 조건과 사용자 override의 소유자> |

공통 진행에서 대상·카메라·라벨·설명을 평가하되 시작점·종료점·hold를 각각 정한다. 모든 전환을 같은 바운스·같은 회전으로 만들지 않는다. 뜻이 이어지는 운동은 경계에서 속도가 갑자기 바뀌지 않게 하고, 설명을 읽을 구간은 실제로 안정시킨다. 표의 숫자는 해당 내용의 편집 결정이며 다른 주제의 기본값으로 승격하지 않는다.

- 시작·감소 모션: <첫 시야의 대상과 시작 행동, OS 설정을 존중한 읽기·직접 조작 경로. 정지한 장면을 위해 긴 빈 스크롤을 요구하지 않는가>
- 설명 시나리오·직접 비교: <시나리오가 바꾸는 조건과 명시적 사용자 선택을 구분. 직접 입력 뒤 무엇을 유지하고, 어떤 행동에서 서사를 다시 따르는가>
- 대표 전환의 반증: <중간→끝→같은 중간과 역방향, 이름표가 가리키는 실제 대상, 도착·읽기 중 가림·여백·초점 경쟁. 기능 PASS와 별도로 관찰>

글자·표현 전환·입구가 중요한 페이지는 다음 중 해당하는 결정만 덧붙인다. 변형되는 장식 글자와 별개로 제목·필수 문장은 읽을 수 있어야 한다.

| 표현 결정 | 이번 내용에서 기록할 것 |
|---|---|
| 원본의 입력 정체성·소유권 | <첫 장면·휠/드래그·재생·복귀 중 보존할 것, 그대로 쓰는 의존성과 명시적으로 수정할 소스. 모션 기본값·직접 켜기/중지·초기화·감소 모션의 관계. metadata 관찰이 카메라·선택·재생을 덮어쓰지 않는 경계> |
| 글자·형태의 인계 | <어떤 제목·윤곽·기준점이 다음 장면의 무엇으로 이어지는가. 실제 font 축·transform·mask·mesh morph를 구분하고 확인하지 않은 지원은 쓰지 않음> |
| 표현과 사실의 경계 | <사진·Gaussian·모델의 같은 부분을 어떻게 대응시키는가. 추정한 뒤·깊이·생성 보완을 실제 자료와 구분> |
| 회전·직접 살펴보기 | <원본 조작과 새로 만드는 조작을 구분. 같은 과업·안내·출처를 전후로 실행해 현재 시점·선택·복귀·감소 모션을 확인> |

### 장면·출입구·대체 표시가 이번 결과의 핵심인 경우

[장면 설계 원리](CINEMATIC_PRINCIPLES.md)와 [Memory 사례](MEMORY_TAPE_CASE_STUDY.md)에서 필요한 결정만 고른다. 정적 문서나 작은 설정 편집에 아래 체계를 새로 만들지 않는다. 같은 의미 상태를 공유하는 것과 모든 요소가 같은 시계·easing을 쓰는 것은 다르다.

| 이번 결과를 바꾸는 결정 | 해당할 때 기록할 내용 |
|---|---|
| 이미지→공간 생성이 있는 경우 | <실제 입력 수·크기·crop·생성/인페인팅의 유무, 모델/가중치/출력 표현·Gaussian 속성, raw→호환 사본→압축→mesh/texture 후처리의 계보. 별도 제공 자산과 이전 출력의 관계·생성 도구 미확인 범위·소프트웨어/모델/원자료 권리. 과거 실행 기록과 이번 재실행/현재 QA를 구분> |
| 관측과 보완, 같은 대상의 등록 | <사진/GS/model의 원자료와 추정면, 고정 anchor·ID·좌표계. 후면·bounds·형상 추가가 관측면을 움직이지 않게 하는 기준. 중복 객체가 있는가> |
| 공간과 독서와 실제 인계 | <카메라의 시작·끝·이어질 속도, 유지/멈출 채널. 문장 완전 표시·마스크·빛·목적지 요청·조작권 반환의 별도 조건. 이 콘텐츠에서 고른 시간과 이유> |
| 현재 윤곽과 빛·마스크 | <현재 camera 또는 실제 표시 frame의 anchor·outline, letterbox 변환의 책임. core/feather/주변/halo의 역할과 내부 보호, 적용하지 않을 형상> |
| live와 이미지·영상의 지원 차이 | <실제 renderer 판별·unknown·명시 review 모드. 공통 의미/문장/목적지와 표현별 입력·도움말·회복. 다른 모드의 성공을 증거로 쓰지 않을 범위> |
| 원자료→파생물→실제 표시 | <capture ref/크기/점 수/LoD/장치, 손실 압축 이력·품질 비교. 원자료 cadence와 RAF, 압축 바이트·decoded 픽셀·fetch·decode 예산. 실제 painted ID와 늦은 요청 무효화> |
| 첫 자세와 읽는 사람의 조작권 | <사진 decode·첫 실제 자세·idle 시작, 실패/시간 초과의 본문 복구. modal/inert/scroll 해제와 visual tail, 사용자 이동 뒤 최종 정리가 덮지 않을 상태> |

Memory의 카세트·초 단위 시간표·64MiB·프레임 수는 해당 사례의 선택이다. 이번 내용의 이유 없이 공용 기본값으로 복사하지 않는다. 기존 구현을 보강하는지 명시적으로 교체하는지 구분하고 이번에 채택한 viewer·motion·미디어 revision을 적는다. 새 설명 observer가 두 번째 재생 상태 owner가 되지 않게 한다. 현재 Memory는 실제 host·scene·모델·캡처 프레임을 사용하는 공개 예제다. 이전 표현의 움직임을 현재의 API나 검증으로 이어 쓰지 않는다.

### 제작 과정을 포트폴리오로 보여 주는 경우

- 전달할 성과와 독자: <디자이너/개발자/사용자가 어떤 판단을 이해해야 하는가. 주역·결과를 첫 화면에서 어떻게 보여 주는가>
- 문제와 선택의 근거: <기대와 실제가 갈라진 장면·직접 원인·더 단순한 대안·선택 이유. 채택/폐기한 안과 적용 조건을 연결>
- 나의 변경과 기존 자산: <원작·기존 엔진·제공 모델·보완한 부분을 구분. source commit·작은 source 링크·권리·출처, 재배포하지 않을 자료>
- 검증과 남은 한계: <코드/파일 무결성/실제 렌더/실제 과업/사용자 연구 중 얻은 증거. 관찰 날짜·ref·renderer·폭·입력과 실패. 과거 검수를 새 후보의 성공으로 이어 쓰지 않음>
- 다른 내용에서의 반증: <가져갈 원리 하나·그대로 옮기지 않을 외형/숫자·반례. 두 번째 콘텐츠에서 확인할 대표 과업>

실제 시스템을 설명하는 사례는 같은 모델·GPU/CPU·미디어·상태로 대표 과업을 보여 준다. 설명 도식을 따로 쓴 경우에는 그 범위를 밝히며 모형 slider의 성공을 실제 renderer의 품질·성능 증거로 사용하지 않는다. 현재 Memory와 제작 사례 별칭은 같은 실제 예제다. 소스 revision·asset manifest·정적 검사·실제 브라우저·공개 미디어·페이지 배포의 확인 상태를 구분한다.

새 콘텐츠에 음성을 붙이면 언어·목소리·속도·높이를 내용과 독자에 맞춰 고른다. 대본·실제 음성·장면 시간·자막의 대응과 합성 출처를 기록하며, 검토한 음성을 다른 음성으로 자동 대체하지 않는다. 이 공개 Memory 예제는 음성을 합성하지 않는다. 온라인 합성을 선택한 새 영상에서는 승인된 대본 범위·실제 사용 도구·비용·실행 결과를 따로 남긴다.

영상은 대표 장면 하나를 다음 표로 편집한 뒤 실제 10–15초를 렌더한다. 각 장면이 같은 판넬 배치를 반복할 필요는 없다.

| 시간 | 이 순간의 주역·변화 | 유지할 관계·카메라 | 문장·소리·관찰 시간 |
|---|---|---|---|
| <시작–종료 초> | <대상 도착→원인 변화→결과 중 하나> | <이전 장면에서 이어지는 대상, 이동 구간과 안정 구간> | <대상 동작 후 들어올 문장, 실제 음성, 읽을 시간> |

검수에서는 “고급스럽다” 대신 **어느 초에 무엇이 시선을 빼앗는가, 라벨이 실제 대상을 가리키는가, 중요한 차이가 화면에서 충분히 큰가**를 적는다. 배경·보조 모델이 주역보다 강하거나, 뜻을 이해하려면 자막부터 해독해야 한다면 대상 크기·명암·구도·진입 순서를 먼저 고친다. 필수 정보와 자막의 안전 여백을 모델이 침범하지 않게 한다.

## 고정할 것과 바꿀 것

- 이번 내용의 불변식: <사실·ID·관계·순서·단위·출처·권한 중 해당하는 것>
- 변형 가능한 축: <이 콘텐츠에서 효과가 있는 표현 선택과 범위>
- 필요한 설명과 상태: <핵심은 보이게, 짧은 보충은 가까이, 긴 배경은 펼침으로; 불필요하면 생략>
- 접근성과 회복: <이 결과에 필요한 읽기 대비·색 외의 의미·키보드/초점·복귀·오류/빈 상태>

기존 공개 제품의 보존과 새 산출물의 표현 선택은 구분한다. 기존 renderer·편집 문서·저장·공개 계약을 지키면서 새 콘텐츠의 강조와 구성을 조정한다. 이미지에는 역할에 맞는 alt·캡션·출처를 두며, 장식 이미지를 실제 화면이나 사실의 증거로 쓰지 않는다.

의존성은 페이지별 계약이다. [Memory의 미디어 계약](MEMORY_TAPE_CASE_STUDY.md#미디어와-공개-전달)처럼 승인된 원본의 큰 자산을 고정 URL로 읽으면 Git·ZIP에서 제외하고 인터넷 요구를 밝힌다. 다른 페이지를 함께 원격화하거나 오프라인으로 바꾸지 않는다. 이전 로컬 구성의 PASS·HEAD/CORS·해시만으로 새 원격 구성의 실제 로딩과 오류 복구를 확인했다고 쓰지 않는다.

## 참고 사례에서 가져온 판단

- 직접 본 범위: <소스 / 갤러리 이미지 / 실제 렌더 / 실제 조작, 자료 이름·URL·확인 시점. 현재 live 동작과 과거 수상·소개 기록은 분리>

| 관찰에서 얻은 원리·근거 | 새 도메인에 대응할 관계와 예상 변화 | 적용 조건·반례 | 실제로 반증할 과업 |
|---|---|---|---|
| <원본의 관찰 범위와 무엇이 함께 변했는가> | <형태를 복제하지 않고 옮길 관계·원인→변화→시각·문장> | <자료·단위·관측자·성능 등 바뀐 제약과 틀릴 수 있는 경우> | <변수 하나 변경, 중간·경계·반대 순서·다른 콘텐츠로 확인> |

- 다른 도메인에 옮길 기준: <같은 관계를 가진 두 번째 사례, 보존할 의미와 다시 고를 표현. 예: 단계→지점·기록의 동기화, 선반cm→에너지Wh의 수량·용량 계산>
- 깨지는 가정: <단순 순서를 인과로, 비교 그림을 물리 성능으로, 안내 완료를 실제 과업 완료로 오해하지 않는 경계>

Memory의 대상 정합·현재 표시 상태·조작권 보존은 새 도메인의 판단 근거다. 카세트·청록색·단계 수·스크롤 driver·시간표를 기본값으로 강제하지 않는다. 제품·관측·환경·자료 탐색으로 옮길 조건과 반례는 [공통 원리](CINEMATIC_PRINCIPLES.md)에 있다.

## 새 콘텐츠와 실제 결과 확인

| 확인할 과업 | 실제 관찰 또는 남은 확인 |
|---|---|
| 행동·상태·회복이 대응한다 | <입력과 그림·문장·근거, 문단·구도 경계의 직전/직후·변화율·역방향·seek, 무관한 입력·모션·history·초기화·도움말 전후 보존의 실제 근거> |
| 미감·관찰 hold를 실제 렌더에서 확인한다 | <식별 형태·명암·타이포·여백, 카메라·강조 순서, 좁은 화면의 대상·설명 근접. reduced-motion/fallback의 읽기 또는 미검증> |
| 전환이 핵심 메시지를 전달한다 | <핵심 자세 사이의 실제 스크롤, 주역의 인계·도착·읽기, 설명과 투영 anchor의 일치. 같은 위치의 복원만으로 연출 품질을 판정하지 않음> |
| 다른 도메인에서도 원리가 맞는다 | <보존한 관계·바꾼 표현·깨진 가정과 반증 결과. 제목·이미지 교체로 대신하지 않음> |
| 처음 보는 사람이 주 과업을 수행한다 | <핵심·다음 행동을 찾고 결과의 의미·제약을 설명하는 실제 과업 관찰. 연구·시험을 안 했으면 미검증> |
| 보고된 실패 조건에서 핵심 과업을 다시 수행한다 | <실제로 보고된 폭·모션 모드에서 단계 점프/프레임 지연/hold를 구별하고, 첫 화면의 모션 선택·인접 전환·입력·복귀를 확인한 근거> |

제목·이미지만 바꾼 복제를 전이 성공으로 취급하지 않는다. 정보 관계가 달라지면 모듈 선택도 다시 판단한다. 정적 검사·스크린샷 한 장·안내를 끝까지 본 기록은 실제 과업의 성공을 대신하지 않는다.

기능 검사는 미감의 증거가 아니다. 사용자가 지정한 레퍼런스와 같은 실제 화면 조건에서 대상의 크기·형태·설명과의 거리·여백·주 조작을 직접 비교한다. 작은 상자·번호·같은 카드를 늘어놓고 문서에서만 아름답다고 판정하지 않는다. 검토와 실제 수정은 [내용에서 출발하는 기준](CINEMATIC_PRINCIPLES.md#내용과-과업에서-출발한다)을 참고한다.

산출물과 실제 소비 경로: <자료/scene/model 원본 → 실제 공용 부품·renderer 또는 해당 페이지 소스 → 실행 HTML·자산 → 이 DESIGN.md>. 편집 JSON·exporter 왕복은 그 페이지가 실제로 지원할 때만 적고, 지원 속성·보관 범위·의존성을 명시한다. 개별 제작 페이지가 임의 JSON으로 자동 생성된다고 약속하지 않는다.

현재 상태: <작성 / 기능 확인 / 실제 GPU 렌더 검수 중 / 과업 시험 / 전달 중 해당 상태와 근거>. 기능·미감·이해·실사용은 각각 관찰한 범위만 보고한다. 확인하지 못한 품질은 미검증으로 남긴다.

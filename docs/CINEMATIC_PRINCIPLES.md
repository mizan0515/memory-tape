# 장면을 읽기와 행동으로 잇는 설계 원리

시네마틱 표현의 목적은 **대상을 알아보고, 변화의 이유를 이해하고, 다음 행동으로 자연스럽게 넘어가게 하는 것**이다. 큰 3D나 긴 전환의 존재가 완성도를 보장하지 않는다. 한눈에 잡히는 주역, 정확한 관계, 충분한 읽기 시간, 되찾을 수 있는 조작권을 함께 설계한다.

이 문서는 Memory Tape에서 얻은 판단을 다른 콘텐츠에 옮기는 공통 기준이다. 실제 구현·비교·폐기 과정은 [Memory Tape 사례](MEMORY_TAPE_CASE_STUDY.md), 새 콘텐츠의 결정 기록은 [DESIGN 템플릿](DESIGN_TEMPLATE.md)을 따른다. [Memory 실제 예제](../memory.html)와 [제작 사례 입구](../memory-making.html)는 같은 host·scene을 사용한다. 실제 카메라·빛·프레임을 별도 SVG/CSS 모형으로 흉내 내어 엔진을 대신하지 않는다. [실행 코드](../memory-scene/viewer.js), [입력](../memory-scene/navigation.js), [전환](../memory-cinematic/overlay.js)과 문서를 함께 읽고 소스·자산 무결성과 실제 브라우저 결과를 구분한다.

## 내용과 과업에서 출발한다

먼저 사용자가 화면을 본 뒤 무엇을 설명하거나 선택할 수 있어야 하는지 적는다. 기록을 읽는 일, 제품을 살펴보는 일, 관계를 이해하는 일, 수치를 비교하는 일은 서로 다른 구도를 요구한다. 공간의 깊이·가려짐·보는 방향이 이해를 바꾸면 3D가 유용하다. 정렬된 문장·사진·도표가 같은 판단을 더 쉽게 전달하면 그 표현을 고른다.

첫 시야에는 주역 하나와 시작할 수 있는 행동을 둔다. 제목·보조 정보·상태·조작은 역할에 맞는 크기와 대비로 구별한다. 대상의 식별 형태와 필요한 설명이 함께 보이도록 여백을 정한다. 장식이 주역보다 크거나 같은 강도의 정보가 동시에 경쟁하면 색을 더하기 전에 구도와 등장 순서를 고친다.

스타일은 내용에 맞춰 고른다. 이야기의 어두운 무대, 제품의 재질, 환경의 밝은 단면, 관리자 작업의 안정된 목록은 달라도 된다. 이 기준의 재사용 단위는 글자·상태·관계·조작·회복의 책임이며 모든 페이지의 카드 모양이나 카메라 경로가 아니다.

## 타이포그래피와 정보의 무게를 편집한다

제목은 장면의 의미를 먼저 잡고, 본문은 이유를 설명하며, caption은 관측·출처·근사의 경계를 밝힌다. 상태·현재 단계·회차는 제목과 같은 힘을 갖지 않게 한다. 큰 글자는 화면을 채우기 위한 장식이 아니라 주역과 읽는 순서를 연결하는 데 쓴다. 필수 제목·문장을 장식 canvas·잘리는 mask 안에만 넣지 않는다.

대상을 볼 때와 문장을 읽을 때의 시선이 경쟁하면 등장 순서를 바꾼다. 배경의 큰 wordmark는 주역의 윤곽을 지우지 않는 대비로 물리고, 근접 관찰에서는 보조 글자를 줄이거나 안정된 여백으로 옮긴다. 좁은 화면에서는 desktop을 단순 축소하지 않고 제목·대상·조작의 관계를 다시 배치한다. 모델을 감춘 뒤 긴 설명을 읽어야 무엇을 보았는지 알게 하면 전개를 고친다.

필수 정보는 문장만으로도 의미가 통해야 하고, 시각물은 그 관계를 더 빠르고 정확하게 보이게 해야 한다. 같은 내용을 큰 글자·작은 글자·번호로 반복해 정보량을 늘리지 않는다. 중요한 차이가 실제 화면의 크기·명암·순서에서 드러나는지 비교하고, 아직 시험하지 않은 이해 효과를 설계 의도와 구분한다.

## 표현이 바뀌어도 같은 대상을 따라간다

사진·Gaussian·mesh·도식·상세 화면 사이에서 무엇이 같은 대상인지 먼저 정한다. 식별 윤곽, 앞면의 그림, 기준점, 선택 ID, 단위와 출처가 후보가 된다. 각 표현의 크기·위치·방향을 대응시키고 현재 표현이 관측 자료인지 추정·창작 보완인지 드러낸다.

모델의 후면이나 두께를 보완하면 전체 bounds가 달라질 수 있다. 그때 매번 bounds에 맞춰 앞면까지 다시 배치하면 관측된 부분이 움직인다. 기존 앞면·손잡이·관측 anchor를 기준으로 등록하고 보완 부위가 그 기준을 바꾸지 않게 한다. 다른 자료의 등록에도 적용할 원리이며 Memory의 수치 행렬 자체를 복사하는 규칙은 아니다.

서로 다른 표현에 같은 대상이 중복되면 교대 방식부터 살핀다. 반투명도를 더 낮추는 것보다 중복 객체를 한 곳에서 제거하고 하나의 대상을 유지하는 편이 정확할 수 있다. 반대로 전후 비교처럼 두 대상이 실제로 달라야 하는 과업에서는 같은 물체로 이어 붙이면 변화가 숨는다.

| 적용할 상황 | 보존할 기준 | 깨지는 경우 |
|---|---|---|
| 사진에서 제품 상세로 접근 | 관측된 윤곽·그림·고정 기준점 | 보이지 않던 뒤를 공식 설계로 소개하거나 앞면을 재배치함 |
| 지도에서 장소 기록을 열기 | 같은 장소 ID·선택 위치·근거 | 장식 핀의 화면 좌표를 실제 지리 위치로 취급함 |
| 도표에서 근거 문서를 열기 | 항목 ID·단위·필터·출처 | 전환 과정에서 조건을 바꾸고 같은 비교라고 설명함 |
| 이야기 장면에서 다시보기로 이동 | 장면·인용 종류·방송 시각 | 다른 장면의 대사를 빌리거나 새 창 성공을 영상 재생 성공으로 간주함 |

## 이미지를 공간으로 바꿀 때 생성의 계보를 남긴다

사진 여러 장을 참고했다는 사실과 여러 시점을 정합해 공간을 복원했다는 사실은 다르다. 실제 모델에 넣은 입력의 수·크기·crop과 전처리, 추론 모델·버전·가중치, 출력 표현을 적는다. XYZ 점인지 위치·색·불투명도·크기·회전을 가진 Gaussian인지, mesh·texture로 바꾼 결과인지 구분한다. 원자료를 개선한다는 이유로 generation·인페인팅·샤프닝을 했다면 그 입력을 관측 자료와 함께 표시한다.

단일 이미지에서 예측한 깊이·뒤쪽을 실측처럼 설명하지 않는다. 보이지 않는 면이 부족하면 카메라 범위를 줄일지, 관측 가능한 다른 자료를 쓸지, 추정임을 밝히고 보완할지 고른다. 공간의 진실성이 필요한 과업에서는 그럴듯한 생성 모델로 빈틈을 메우는 방법이 맞지 않을 수 있다. 사진 기반 제품 소개·팬 시각 실험에서 허용한 근사를 의료·치수·안전 판단으로 전이하지 않는다.

후속 자산을 별도로 제공받았으면 앞선 추론 결과의 단순 최적화라고 합치지 않는다. 각 파일이 어떤 입력·도구·형상·질감 후처리에서 나왔는지 연결하고, 일부 속성의 보존을 전체 무손실로 확대하지 않는다. 원본 보존, 호환용 정규화, 점 제거, 압축, GPU 캡처는 서로 다른 변환이다. 소프트웨어·가중치·원자료·생성 결과의 권리도 나눠 확인한다.

[Memory의 실제 입력과 생성 기록](MEMORY_TAPE_CASE_STUDY.md#이미지에서-gaussian-장면과-카세트-모델을-만들기)은 최초 SHARP/TripoSR 실행과 이후 자산 재사용을 구분한다. 원 제작의 로그·검수, 현재 파일의 hash·치수, 현재 브라우저 동작은 각각 답하는 질문이 다르다.

## 원인 변수와 카메라를 분리한다

달의 공전 위치를 바꾸는 일과 같은 달을 다른 방향에서 보는 일은 다르다. 제품의 각도·빛을 바꾸는 일과 카메라를 돌리는 일도 다르다. 도메인 입력, 대상 상태, 카메라 자세, DOM 설명을 구별하고 같은 의미 상태를 소비하게 한다. 자유 관람이 이미 작동하면 새 스크롤 driver를 덧씌우지 않고 기존 입력·감쇠·재생 인계를 보존한다.

두 자세를 연결할 때는 대상이 보이는 구간의 방향·거리 변화를 먼저 검토한다. 양의 거리는 로그 공간 보간이 적합할 수 있지만 모든 장면의 정답은 아니다. 큰 회전이 대상이 가려진 뒤에만 일어나거나 카메라가 모델을 관통하면 끝점·주시점·경로를 바꾼다. 키를 두 개로 줄였다는 사실만으로 좋은 경로가 되지는 않는다.

사용자가 움직이던 자세에서 자동 재생으로 넘어갈 때는 위치와 방향뿐 아니라 이어져야 할 속도를 확인한다. 들어오던 yaw·거리 속도를 보존할 수 있고, 읽기를 방해하는 pitch·roll은 의도적으로 고정할 수 있다. 어떤 채널을 유지하고 멈췄는지 적으며 일부 채널의 매끄러움을 모든 카메라 축의 연속성으로 확대하지 않는다.

## 카메라와 읽기와 인계에는 서로 다른 시간이 있다

전개의 공통 상태는 필요하지만 모든 일을 같은 progress와 easing에 묶을 이유는 없다. 카메라는 대상을 찾고, 문장은 의미를 읽게 하고, 마스크는 앞 장면을 걷고, 링크는 실제 목적지로 이동한다. 각 책임의 시작·끝·안정 구간을 정하고 서로 겹칠 순서를 편집한다.

문장이 카메라의 가속 때문에 너무 빨리 사라지면 독서 시계를 분리한다. 화면이 충분히 열렸는데 장식의 마지막 fade를 기다리느라 본문을 조작할 수 없다면 시각적 마무리와 조작권 복귀를 분리한다. 짧은 계산·목록 작업에는 긴 전환을 추가하지 않는다. Memory의 4.5·7.8·6.35·3.45초는 해당 문장과 연출에서 선택한 사례 값이다.

수동 입력은 현재 상태를 바꿀 권한이다. 명시적으로 시작한 짧은 전환에서만 입력을 잠그고 취소·본문 복귀를 제공한다. 자동 서사가 사용자의 비교 조건이나 선택을 다시 덮지 않게 한다. history·다시 열기·도움말도 어떤 상태를 보존하는지 정한다.

## 마스크와 빛은 현재 보이는 대상에 붙인다

회전하는 대상의 출입구가 필요하면 현재 카메라에서 윤곽을 투영한다. 실루엣·anchor·라벨이 어떤 좌표계에 속하는지 정하고 화면의 letterbox·여백 변환은 한 번만 적용한다. 고정 도식에서는 이 투영 체계를 새로 만들 필요가 없다.

대상 모양의 core, 넓게 퍼지는 페더, 주변의 불투명도는 역할이 다를 수 있다. 하나의 blur만 키워 모든 영역을 동시에 지우기보다 무엇이 먼저 사라져야 하는지 선택한다. 광원이 대상의 바깥을 밝히는 연출이라면 내부 cutout으로 표면을 보호한다. 빛이 실제 물리 광원이나 재질 변화의 증거인 것처럼 설명하지 않는다.

래스터 마스크를 크게 늘리면 가장자리 계단이나 원래 자세와의 불일치가 드러날 수 있다. 벡터 윤곽은 하나의 대안이다. convex hull이 오목한 구멍·복잡한 부품 관계를 지워 버리는 대상이라면 다른 표현을 고른다. 모든 모델에 Memory의 둥근 카세트 윤곽을 강제하지 않는다.

## 표시 방식이 달라도 의미와 상태를 맞춘다

가속이 충분한 live 장면과 가속이 없는 이미지 재생은 지원하는 조작이 다르다. 공통으로 유지할 것은 대상·문장·진행·목적지·회복이며 자유 3D 회전까지 같다고 약속하지 않는다. 장치 이름이나 user agent만으로 실제 가속을 단정하지 않고 확인한 renderer와 미확인 상태를 구별한다.

미리 그린 프레임을 쓰면 예정된 목표와 실제 표시한 프레임이 다를 수 있다. 마스크·라벨·반경은 실제 표시한 프레임의 ID와 metadata에 연결한다. 역방향 입력·resize·숨김·재진입 뒤 늦게 끝난 decode가 오래된 장면을 다시 그리지 않게 한다. 현재 목표 우선과 필요한 미래 표본만 준비하는 방식은 메모리와 입력 응답을 함께 지킨다.

압축 바이트, decoded 픽셀, 동시 fetch, decoder 수는 다른 예산이다. 많은 고해상도 이미지를 모두 decoded 상태로 보관하지 않는다. 해상도 선택은 실제 표시 크기와 DPR에서 정하고 재선택 비용·품질 요구에 따라 페이지 동안 유지할지 판단한다. 특정 사례의 64MiB·4장·2fetch를 범용 기본값으로 고정하지 않는다.

첫 사진, 첫 실제 자세, idle 시작도 다른 상태다. 첫 사진과 같은 자세가 준비된 뒤 전환하면 로딩 동안 이미 회전한 장면이 갑자기 나타나는 일을 줄일 수 있다. 로딩 cover가 끝없이 본문을 막지 않게 오류·시간 초과·직접 읽기 경로를 둔다.

## 품질은 파생 과정과 확인 범위를 함께 기록한다

해상도·프레임 수·코덱 quality 숫자는 지각 품질의 대리 지표다. 이미 손실 압축된 WebP를 AVIF로 바꿨으면 그 파생 관계를 적고 무손실 master라고 부르지 않는다. 서로 다른 코덱의 quality 50·80·90을 같은 척도로 비교하지 않는다. 작은 표본에서의 decode 시간은 전체 재생 FPS·모든 장치의 성능을 입증하지 않는다.

같은 자세·동일 표시 크기의 대표 표본에서 얼굴·미세 글자·윤곽·그라데이션·움직임을 비교한다. 파일 크기·독립 decode·해시·치수 검사는 전송 무결성을, 실제 전경 재생은 표시 품질을, 사용자 과업은 이해를 각각 확인한다. rAF 횟수와 서로 다른 이미지의 교체 빈도를 구분하고 숨김 창의 간격을 전경 FPS로 보고하지 않는다.

도움말은 실제 표현을 따른다. GPU 자유 회전에는 회전·접근을, 이미지에는 스크롤·세로 쓸기를 안내한다. 반복 작업면의 핵심 행동을 투어에 숨기지 않으며 필요가 확인된 경우에만 선택형 짧은 투어를 둔다. 감소 모션·정지 선택은 페이지의 목적과 승인된 범위에 맞춰 설계하고 한 사례의 예외를 다른 페이지 기본값으로 복제하지 않는다.

## 의존성과 전달도 경험의 일부다

원본·코드·글꼴·미디어의 출처와 권리를 먼저 구분한다. 고정한 원격 자산을 읽는 선택에는 인터넷 요구·실패·재시도·대체 읽기를 함께 둔다. 큰 파일을 ZIP에 넣지 않았다는 사실이 영구 가용성이나 재배포 권한을 보장하지 않는다. 로컬 개인용 키트·비공개 preview·공개 웹은 서로 다른 전달 경계다.

자산 해시·manifest는 같은 바이트를 찾고 복구하는 근거다. 공개 자료인지, 원문·개인정보를 전송해도 되는지까지 판정하는 권한은 아니다. CORS·Origin/Referer 기반 hotlink 제한과 사용자 인증·DRM을 혼동하지 않는다. 구현 소스·local 검증·업로드·배포·실행 세션의 채택도 각각 확인한 상태로 기록한다.

## 제작 과정은 선택의 이유를 보여 준다

포트폴리오는 효과의 목록보다 사용자 문제와 해결의 연결을 보여 준다. 기대와 실제가 처음 갈라진 장면, 그 원인, 선택한 최소 수정, 폐기한 대안, 결과를 확인한 과업 순으로 읽게 한다. 기존 엔진·제공 자산·직접 바꾼 부분을 구분해 독자가 작업의 기여를 판단할 수 있게 한다.

실제 시스템의 제작 사례라면 같은 engine·모델·미디어와 상태를 사용해 판단을 보여 준다. 원리를 설명하는 별도 도식이 필요하면 설명 범위를 밝히고 실제 제품 결과와 구분한다. 모형 slider의 동작을 원래 제품의 GPU 성능이나 모델 품질의 증거로 바꾸지 않는다. 상세 소스·기존 증거는 필요한 곳에서 열고 핵심 문장을 그 링크 뒤에 숨기지 않는다. Memory의 현재 템플릿과 제작 사례 입구는 같은 실제 구현이며 과거 설명용 모형은 현재 채택 경로가 아니다.

## 다른 도메인으로 옮길 때의 판단

| 새 과업 | 옮길 원리 | 다시 고를 표현·반례 |
|---|---|---|
| 박물관 유물의 관측·보완 소개 | 관측면·추정면 구분, 고정 등록, 현재 윤곽 | 실측하지 않은 내부를 복원 사실로 표시하지 않음. 안정된 사진 비교가 낫다면 3D 생략 |
| 제품 분해·사용법 | 같은 물체와 부품 ID, 카메라·읽기 시간 분리 | 분해 거리를 실제 치수로 암시하지 않음. 단순 설정 변경을 긴 영화로 지연하지 않음 |
| 환경의 흐름·단면 비교 | 원인 조건 고정, 실제 경로와 설명의 일치 | 영상 속 입자 수를 실제 유량으로 읽게 하지 않음. 가상 모델의 안전 예측 금지 |
| 지도·문서·데이터 탐색 | 선택 ID·필터·근거와 조작권 보존 | 의미 없는 포털을 추가하지 않음. 즉시 비교·복귀가 우선인 목록은 안정적으로 유지 |
| 이야기·방송의 다시보기 | 검증된 문장·시각, 현재 맥락에서 목적지 인계 | 인용과 화면 문구 구분. 팝업 차단·뒤로가기를 정상 상태로 다룸 |

## 근거를 평가하는 방식

| 주장 | 필요한 근거 | 그 근거만으로 말할 수 없는 것 |
|---|---|---|
| 같은 상태를 다시 만든다 | 원인 입력·정/역방향·중간 seek·복귀의 상태 대조 | 미감·읽기 시간·사용자 이해 |
| 전환이 대상을 이어 준다 | 같은 조건의 실제 렌더와 현재 anchor·윤곽 확인 | 모든 시점·모든 모델의 정합 |
| 읽고 조작할 수 있다 | 문장 표시 구간, 초점·취소·본문 스크롤의 실제 과업 | 처음 보는 사용자의 이해 향상 |
| 더 작고 적절한 파생물이다 | 크기·출처·decode 무결성·대표 품질 비교 | 무손실·모든 기기의 성능 |
| 전달·운영에 반영됐다 | 해당 ref의 패키지·서버·실행 모듈·공개 URL 각각의 확인 | 소스 merge만으로 운영 채택 |

관찰 날짜·ref·renderer·표시 크기·입력·결과·한계를 짧게 남긴다. 기능 확인, 시각 검수, 실제 과업, 연구 결과를 서로 대신 쓰지 않는다. 통과한 검사 수보다 주역·의미·조작권이 대표 흐름에서 함께 유지되는지가 완료 기준이다.
